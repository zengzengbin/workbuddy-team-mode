# 小队模式 · 角色模型一次性选型菜单

## 用途（写给 WorkBuddy AI）

本文件是"小队模式角色模型一次性选型"的菜单与执行脚本。**只在首次启用小队模式、且配置文件缺失或损坏时**读取并执行本文件；配置就绪后不再读取本文件，后续每次使用小队模式直接读取配置。

- 配置文件路径：`skill/references/team-config.md`（与本文件同目录，由 `team-config.template.md` 模板生成）。
- 触发条件（满足任一即执行本文件）：
  1. `team-config.md` 不存在；
  2. `team-config.md` 存在但无法解析（缺角色行、占位符未替换、表格损坏）。
- 触发条件不满足时：**禁止**打开本文件、禁止重新询问选型。

---

## 选型流程（AI 执行步骤）

1. **一次性摆出完整菜单**：在同一条回复里给出下面三节内容——
   - A. 供应商与模型罗列表（按国内版 / 国际版 / 自定义分组）；
   - B. 思考强度罗列表（五档）；
   - C. 四角色推荐表（三套整体方案 + 单角色微调说明）。
2. **请用户选择**：优先请用户从三套整体方案（均衡 / 经济 / 顶配）中选一套；再询问是否需要对个别角色做微调（换模型或换档位）。用户也可以逐角色自行组合。
3. **逐角色确认**：把最终四角色组合（含备选）列成一张表，请用户确认。
4. **写入配置**：用 `team-config.template.md` 模板，把确认结果填入，另存为 `skill/references/team-config.md`（UTF-8）。模板中所有 `<待填：…>` 占位符必须全部替换为实际值。
5. **复述最终配置**：向用户复述写入的四角色配置，并告知配置文件路径，说明"以后不再询问，除非配置缺失或损坏"。

**禁止事项**：
- 禁止每轮对话重复询问模型选择；
- 禁止在 `team-config.md` 已存在且可解析时重新走选型；
- 禁止编造 WorkBuddy 不存在的型号版本号（以系列名为准，具体型号以用户 WorkBuddy 实际 UI 为准）；
- 禁止在派发任务时声称平台已按配置强制固定了模型（见"平台限制"一节）。

## B. 思考强度罗列表（产品级档位选择器）

| 档位 | 一句话适用场景 |
|---|---|
| Default | 推荐默认，平台自动平衡质量与速度 |
| Fast | 追求最快响应：简单定位、格式转换、短问答 |
| Balanced | 质量与速度折中：常规编码、常规评审 |
| Primary | 更重推理：复杂实现、跨文件改动 |
| Deep | 最重推理：架构决策、疑难诊断、严格终审 |

## C. 四角色推荐表（三套整体方案 + 单角色微调）

### 角色回顾

| 角色 | 职责 | 对模型的核心诉求 |
|---|---|---|
| 探索（explorer） | 只读定位代码与证据 | 快、准、便宜 |
| 执行（executor） | 实现并验证 | 编码能力强 |
| 评审（reviewer） | 独立只读评审 | 严格、长上下文 |
| 专家顾问（expert-advisor） | 复杂决策/诊断 | 最强推理 |

### 方案一：均衡档（默认推荐，国内版示例）

| 角色 | 首选 | 备选 |
|---|---|---|
| 探索 | GLM + Fast | MiniMax + Fast |
| 执行 | DeepSeek + Primary | GLM + Balanced |
| 评审 | Kimi + Balanced | 混元 + Balanced |
| 专家顾问 | Kimi + Deep | DeepSeek + Deep |

理由：探索求快求省；执行上代码最强的 DeepSeek；评审用长上下文的 Kimi；顾问给最高档位。整体花费适中，国内版开箱即用。

### 方案二：经济档（成本优先）

| 角色 | 首选 | 备选 |
|---|---|---|
| 探索 | GLM + Fast | 混元 + Fast |
| 执行 | DeepSeek + Balanced | GLM + Balanced |
| 评审 | GLM + Balanced | DeepSeek + Balanced |
| 专家顾问 | DeepSeek + Deep | GLM + Deep |

理由：全部落在高性价比国产模型上，档位整体下调一档，适合高频使用、预算敏感的用户。

### 方案三：顶配档（质量优先，需国际版或自定义渠道）

| 角色 | 首选 | 备选 |
|---|---|---|
| 探索 | Gemini + Fast | GPT-5 + Fast |
| 执行 | Claude + Primary | GPT-5 + Primary |
| 评审 | Claude + Balanced | Gemini + Balanced |
| 专家顾问 | Claude + Deep | GPT-5 + Deep |

理由：综合最强梯队，适合对产出质量最敏感的场景；成本最高。

### 单角色微调

用户选定整体方案后，可对任意角色单独换模型或换档位（例如"顾问我要 Kimi + Deep"）。微调后的最终组合以用户确认为准。

> 若用户只有部分模型可用：用"自定义模型（自有 API Key）"兜底，或在可用模型内按上述"核心诉求"就近替换，并向用户说明替换理由。

## 平台限制（如实告知用户，不得省略）

WorkBuddy 平台当前**不支持**按成员固定模型：

- 专家/专家团的 agent md frontmatter 只有 name、description、displayName、profession、maxTurns、skills，**没有 model / thoughtLevel / reasoning 字段**；模型与工具权限由系统统一分配。
- 派发成员用内置 AgentTool，参数只有成员角色名，**不能按调用指定模型**。

因此本配置的现实定位是"三位一体"：

1. **意图记录**：`team-config.md` 记录用户为每个角色选定的模型与档位意图；
2. **派发声明**：主 Agent 用 AgentTool 派发时，在任务说明中写明"该角色应按配置使用 X 模型 / Y 档位的标准执行"，由成员 Agent 在其可用能力范围内对齐；
3. **UI 档位建议**：同时告知用户——如需更严格的模型/档位控制，请在 WorkBuddy UI 的模型下拉与思考档位选择器中手动设置（具体入口以用户 WorkBuddy 实际 UI 为准）。

**禁止**向用户暗示"写入配置后平台会强制每个角色用指定模型"。

## 常见问题（FAQ）

**Q1：用户的 WorkBuddy 里只有部分模型可用怎么办？**
A：只展示用户实际可用的分组；缺位角色用"自定义模型（自有 API Key）"兜底，或按各角色"核心诉求"在可用模型中就近替换，并向用户说明。

**Q2：用户说"都按推荐来"，怎么处理？**
A：直接套用方案一（均衡档）作为默认方案，逐角色列出并一键确认后写入 `team-config.md`，不再逐项追问。

**Q3：用户是国际版，没有国产模型？**
A：推荐整体切换到方案三的模型家族；经济需求则在国际版可用模型中选响应更快/更便宜的组合，理由照旧说明。

**Q4：用户之后想改配置怎么办？**
A：引导用户直接编辑 `skill/references/team-config.md`（或删除该文件后重新触发本选型流程）。正常工作流程中 AI 不得主动重问。
